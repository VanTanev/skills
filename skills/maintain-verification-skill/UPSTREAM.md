## Local changes

All changes let Claude Code, OpenCode, and other agents run the skill from one canonical copy in `.agents/skills`.

- Frontmatter: keeps `disable-model-invocation: true`, which Claude Code and Cursor read, and adds `metadata.opencode/autoinvoke: false`, the OpenCode form of the same setting.
- Description: the "Use for /maintain-verification-skill or \"audit the verify skill\"" trigger list is removed.
  Model invocation is off, so trigger phrases for the model contradict the frontmatter, and agents do not all start skills with a slash command.
- Intro: "generated by `/create-verification-skill`" becomes "generated by the `create-verification-skill` skill", for the same reason.
- Step 1: a symlink and its target are one match, and the agent edits the target under `.agents/skills`, because `.claude/skills/verify-*` is only its compatibility symlink.
  Without this, the symlink gives two matches and the skill always asks which one.
- Step 1: "stop and point at `/create-verification-skill`" becomes "stop and offer to call the Skill tool with "create-verification-skill"", the agent-agnostic form that Matt Pocock's skills use.
- Step 3: "on the `swarm workers` model" is removed, because it names a pstack model role that other agents do not have.
- Run notes: "show-me-your-work log" becomes "log", because this repo does not vendor the pstack `show-me-your-work` skill.
- `agents/openai.yaml`: added, with `policy.allow_implicit_invocation: false`, the Codex form of the same setting.
- `LICENSE`: added as a byte copy of upstream `pstack/LICENSE` (MIT), to keep the license notice with the copy.

## Update procedure

Update this skill together with `create-verification-skill`, because both use the `verify-<app>` layout.

1. In an up-to-date clone of https://github.com/cursor/plugins, run `git fetch origin main pull/334/head:pr-334` and `gh pr view -R cursor/plugins 334 --json state,headRefOid`.
2. Pick the new upstream ref.
   If PR 334 is merged, the ref is `origin/main`.
   If PR 334 is open, the ref is `pr-334`.
   If PR 334 is closed without a merge, ask the user whether to keep its changes.
   If PR 334 is open and `git diff <base>..origin/main -- pstack/skills/maintain-verification-skill/` is not empty, `main` also changed this skill: ask the user how to combine the two.
3. Compare: run `git diff <plus-sha>..<ref> -- pstack/skills/maintain-verification-skill/SKILL.md` and `git diff <base>..origin/main -- pstack/LICENSE`.
   If both are empty, set "Checked up to" to the `origin/main` SHA and date, and stop.
4. In this directory, run `git -C <clone> show <ref>:pstack/skills/maintain-verification-skill/SKILL.md > SKILL.md`, and copy `pstack/LICENSE` from `origin/main` to `LICENSE`.
   Keep `UPSTREAM.md` and `agents/openai.yaml`.
5. Re-apply the local changes: in this directory, run `sed -n '/^```diff$/,/^```$/p' UPSTREAM.md | sed '1d;$d' | patch -p1`.
   If a hunk fails, apply that change by hand from the list above.
6. In this file, replace the diff with the output of `diff -u --label a/SKILL.md --label b/SKILL.md <(git -C <clone> show <ref>:pstack/skills/maintain-verification-skill/SKILL.md) SKILL.md`.
   Update "Base", "Plus", and "Checked up to": after a merge, "Base" is the merge commit and "Plus" goes away; while the PR is open, "Plus" is its new head SHA.
